# Verification Gate（完工自证铁律）
1. 永远不要只凭肉眼读代码就宣布「修好了」。必须实际运行构建命令、语法检查（如 `node --check`）与关键路由产物校验。
2. 检查边界退化：空数据状态、长文本溢出、深浅色主题切换、带子路径（`BASE_PATH`）部署时的静态资源引用。
3. 汇报时只陈述已实际验证通过的事实与文件位置，未测到的环节明确标出。

# Context Handoff（五格交接单）
当任务需要跨会话接力时，输出干净的五格交接单：
- 最终目标（一句话）
- 已完成并通过验证的事项
- 已踩过并明确排除的死路（接班必看）
- 关键文件精确路径
- 下一棒唯一聚焦动作
