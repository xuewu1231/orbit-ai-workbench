在用 AI 写网页、做组件库或者生成代码视频的过程中，最常见的一个困惑是：**为什么脑子里明明想的是 Apple 发布会和 Linear 官网那种干净利落的质感，嘴上告诉 AI「请帮我做得高级、现代、丝滑一点」，最后拿到的却是满屏蓝紫霓虹渐变、粗黑边框配火箭 Emoji？**

答案其实非常底层：**大模型的默认输出，是全网公开代码库审美分布的「数学平均值」。**

当你输入「高级、炫酷、科技感」这种模糊形容词时，模型不知道你的「高级」指的是留白克制还是赛博发光，于是它会顺着概率最高、训练语料里最泛滥的营销模板往下滑。想要打破这种平庸引力，提示词的核心功夫只有一件事——**把感性的「品味词」，翻译成确定性的「物理参数与负面禁令」**。

## 一、四维参数翻译表：把「感觉」变成 AI 听得懂的硬指标

以后在写提示词时，只要发现自己打出了「好看、舒服、丝滑、有冲击力」这几个词，立刻停下来，对照下面这张表把它替换成具体参数：

| 你脑子里的感觉 | 千万别这样写（必翻车） | 应该这样写进提示词（一遍到位） |
| :--- | :--- | :--- |
| **界面干净耐看** | “做一个极简高端、呼吸感强的页面” | “画布底用 `#F6F7F9`，内卡片用纯白 `#FFFFFF`，主文字 `#0A0A0B`，全页只保留一个 `#2563EB` 强调色（面积不超过 2%），区块上下间距留足 `64px`” |
| **卡片有精致层次** | “卡片要有立体感、别太单调” | “采用外灰内白双层嵌套（外壳圆角 `24px` + `1px` 极淡边框，内嵌白卡圆角 `16px`），配两层极低透明度漫射阴影，禁用粗黑边框和霓虹发光” |
| **交互动效丝滑** | “加一点丝滑炫酷的动画效果” | “严禁 `linear` 匀速；悬停用 `cubic-bezier(0.22, 1, 0.36, 1)` 微抬 `2px`；代码视频卡片入场用物理弹簧 `stiffness: 210, damping: 20`，列表每项错峰延迟 `4` 帧” |
| **视频镜头有电影感** | “镜头切换要有节奏感，别像 PPT” | “外层套 `CameraRig` 虚拟摄像机：第 `30–60` 帧推镜至 `scale(1.6)` 锁定核心按钮并压暗背景 `65%`；章节切换用 `14` 帧高速甩镜（Whip Pan）叠水平模糊” |
| **排版专业可信** | “字体排版要讲究一点、工整一点” | “主标题字重 `800`、字距收紧 `-0.03em`；正文最大宽度 `720px`、行高 `1.75`；所有数字开启 `tabular-nums` 等宽对齐；全面禁用彩色 Emoji” |

## 二、别让 AI 一上来就闷头写代码：三步渐进式描述法

哪怕参数给得再细，如果试图靠**一段超长提示词让 AI 一次性吐出上千行完整页面或整支视频代码**，成功率依然不高。因为模型在同时应付「内容编排 + 视觉布局 + 边界逻辑」时，顾头不顾尾是常态。

最稳、返工最少的描述方式，是拆成清晰的**三步对话节奏**：

### 第 1 步：只定结构与分镜，严禁写代码
第一轮对话明确下令：**「先不要写任何代码，先把结构拆出来让我确认。」**
- 如果是**写网页/功能模块**：让它先用三句话列出改哪几个文件、页面从上到下分哪几个区块、不碰哪些旧模块。
- 如果是**做代码视频**：让它先把文稿拆成「帧级分镜表」——每一幕起止帧号、画面上唯一保留的视觉元素（不超过 15 个字）、以及对应的运镜术语（推镜 / 拉镜 / 甩镜 / 匹配变形）。
- 在文字阶段改结构只需要 10 秒钟；等它写完 800 行代码再推翻重来要花半小时。

### 第 2 步：确认骨架后，挂载「可执行规范」写码
当结构或分镜表完全符合预期后，第二轮再把我们在弹药库第一栏沉淀好的**纯文本可执行规范**（如《界面四色去塑料规范》或《代码视频纯帧号确定性规范》）原封不动贴进去，让它严格在护栏内生成代码。

### 第 3 步：局部手术刀精修，一次只改一个点
初版跑出来如果有 80 分，切忌说一句笼统的「再优化一下整体质感」——这会让 AI 把原本写对的地方也胡乱改掉。正确的修法是**指哪打哪**：
- 明确锁死范围：*“其他区块保持一字不动，只修改第 2 幕第 `40–75` 帧的按钮点击段落：补上一颗沿贝塞尔弧线滑入的光标，点击瞬间加 `scale(0.95)` 回弹与扩散圆环波纹。”*

## 三、前后真实提示词反差实例

最后放一组最直观的对比，看看同样是做一段「产品核心功能演示镜头」，两种描述方式会带来多大的天壤之别：

```text
【反面写法 · 模糊偷懒指令】
帮我用 React 写一段好看的产品宣传视频开头，展示我们的一键复制给 AI 功能，要有高级科技感，动画丝滑一点，吸引眼球。
```

```text
【正面写法 · 结构化参数与规范指令】
任务：编写一支 60fps（1920×1080）代码视频的第 1 幕组件 Scene01PromptCopy.tsx，总时长 150 帧（2.5 秒）。

1. 视觉底座：采用 Keynote 纯白精密风（画布 #F5F5F7、外灰内白双层卡 #FFFFFF、主字 #0A0A0B、强调色 #2563EB；严禁蓝紫渐变与 Emoji，四周预留 10% 安全边距）。
2. 帧级镜头与动作编排：
   - 第 0–28 帧：真实矢量还原产品收藏卡片，带 CARD_SPRING（damping:20, stiffness:210）从微缩 0.94 平滑定格居中。
   - 第 32–64 帧：外层 CameraRig 从 scale(1.0) 平滑推进至 scale(1.55) 聚焦右下角「复制给 AI」按钮，同时周围非焦点区域微压暗；矢量光标沿弧线滑至按钮上方。
   - 第 68 帧：触发按钮按压 TAP_SPRING（scale 0.95 → 1.0）与蓝色半透明圆环波纹，按钮文字切换为「已复制纯文本指令」。
   - 第 90–135 帧：右侧顺势滑出纯文本提示词预览抽屉，内部三行结构化条目按每项间隔 4 帧错峰（Stagger）浮现。
3. 工程红线：严禁使用 CSS transition / animation / setTimeout，全部样式 100% 由 frame 纯函数与 clamp 钳制插值计算得出。
```

当你养成用下面这种方式和 AI 沟通的习惯，你会发现：**决定上限的从来不是什么神秘口诀，而是你对好作品的拆解颗粒度。**把每一次调出来的满意参数顺手记回弹药库的规范文档里，下一次开工就又省掉一半力气。
