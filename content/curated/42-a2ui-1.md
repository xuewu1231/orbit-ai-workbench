谷歌把 A2UI 收到了 1.0。要解决的事很具体：Agent 查完库存、算完报价，最后常常只能回一大段字。人要的是能填、能点、能看的界面。

各家库各自发明一套描述界面的办法，结果被锁在某个框架上，也跟产品自己的设计语言对不上。A2UI 把这件事拆开：Agent 只交一份数据，说明用户该看到哪些组件、它们怎么连、数据从哪来；真正画出来的，是应用里已经有的组件。

目录里没有的东西，到不了屏幕。传来的是数据，不是一段可执行代码。界面被拆成一小段一小段的 JSON，用编号互相指，Agent 边写，应用边画。同一份描述可以在网页和手机上各画各的。官方渲染器覆盖 React、Angular、Lit、Flutter、SwiftUI 和 Jetpack Compose，社区还有 Vue 和终端。

另外有一种更紧的写法，叫 A2UI Express。它少占模型输出，也少一些等待，而且不依赖工具调用，模型可以直接写。

0.9 解决的是「模型能不能稳定写出这份描述」。1.0 把它往能上线的方向推了一步。相对上一版，值得记住的是这八处。

## 两边都能调函数

界面可以直接调 Agent 上的函数，比如核对一个编号、查一次库存，结果回到发起的那个组件。Agent 也能反过来问只有这台设备才知道的事，比如屏幕有多大。本地有的函数就在本地跑，没有就交给 Agent。哪一侧允许调什么，由组件目录决定，渲染时逐条核对。

## 一个界面可以用多套组件库

真实产品很少只用一套组件。一块看板可能同时要基础布局、自家设计系统和一份地图。以前一个画面锁在一套目录上。现在每个组件可以自带自己的目录地址，画面只给一个默认。指定的目录不在，渲染器会直接报错，不会悄悄换一套库来画。

## 设计规则写进目录

目录不再只是一张组件名单。可以规定谁能套进谁。模型放错位置，会拿到指明哪条规则的错误，便于它自己改。用法说明、设计 token、已经废弃的组件和替代方案，也可以放在同一份目录里。

## 一条消息画出整个界面

以前要先建画面、再加组件、再送数据。现在一条创建消息可以带齐组件和数据，消息一到，界面就在。大的界面仍然可以拆开，边生成边画。调试时，整份界面就在一条能记下、能重放的消息里。

## 校验带回错误码

不再只有过或不过，外加一句固定的话。结果可以带错误码、说明和级别：硬错误、提醒，或只是一条信息。表单因此既能拦住错误，也能给一句轻一点的提示。校验还可以放到 Agent 那边，去查当时的数据。

## 有副作用的动作必须人来点

会跳出当前页面、或把内容送出去的函数，可以要求一次真实的点击。否则界面刚画出来，就可能自己把人带去别处。渲染过程里，或只是数据绑定时，渲染器会拦住它们。

## 无障碍写进规范

标签和描述要接到各平台的无障碍接口：网页上是 ARIA，Flutter 里是 Semantics。没写标签时，渲染器会用看得见的文字，按钮上写着「提交」，读出来也是「提交」。还在更新的状态行，也可以用不过分打断的方式念出来。

## @ 专门留给协议

读数据、调函数，都改用 @ 开头。这样业务数据里如果本来就有 path、call 这样的字段，比如一份文件记录，不会被当成指令。带 @ 的是协议，不带的是你的数据。

规范本身不接受没声明过的字段。要挂自己的信息，比如访问策略或审计签名，走带命名空间的扩展。渲染器不认识的键，直接忽略。

## 从 0.9 迁过来

1.0 和 0.9 不兼容。大部分改动是机械的：改版本号，给绑定和调用加上 @，把样式从协议里拿掉，改由应用自己管。两种版本的画面可以同时存在，可以一个界面一个界面地换。

想少写一层适配，CopilotKit 的生成式界面是按 A2UI 1.0 做的，并且走在 AG-UI 上。已经接了 AG-UI 的框架，比如 LangChain、Mastra、Google ADK，可以沿这条路接进来。标准目录里有一批现成组件，也可以把自己的组件登记进去，告诉 Agent 什么时候该用它。

界面变成 Agent 可以组装的积木之后，做前端的人少画一张张固定的页，多设计积木，以及 Agent 不许越过去的规则。
