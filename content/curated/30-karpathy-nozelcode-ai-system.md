大多数人之所以没能榨出大模型真正的潜力，往往不是因为工具装得太少，恰恰是因为**把简单的事情搞得太复杂，却在最核心的上下文与工作流上偷了懒**。

OpenAI 联合创始人 Andrej Karpathy 在这段长达 70 分钟的桌面实录里，没有放一页修饰过的发布会幻灯片，全程只是打开浏览器、Excalidraw 手绘白板和真实的模型窗口，演示他自己在日常工程与研究里究竟怎么跟大模型配合。技术博主 roman（`@Nozelcode`）将这堂实战大师课浓缩成了极其清晰的骨架：**先立住正确的大模型物理直觉，打牢「四大日常支柱」，再跨过「三大系统原语」的分水岭，从单次聊天升级为让系统替你干活。**

## 第一层直觉：大模型不是全知神明，而是一个「1TB 的互联网有损压缩包」

在实录开场的 Excalidraw 白板上，Karpathy 画了一个让人瞬间清醒的比喻——如果你让大模型做自我介绍，最诚实的台词应该是：

> 「你好，我是一个大约 1TB 大小的 zip 压缩文件。我的知识来自半年多前读过的互联网网页，预训练花了几千万美金算力把它们有损压缩进了参数权重里，所以我对很多细节只记得大概的模糊印象；而我讨喜的说话方式，是后训练阶段（SFT / RLHF 与强化学习）按人类示范调教出来的。」

一旦你在脑子里钉死这个物理画面，平时用 AI 踩过的无数坑就全想通了：

:::diagram-karpathy-zip-memory:::

- **参数权重（Parametric Memory）是有损且滞后的**：就像把高清原图压成极小的缩略图，模型记住了强大的逻辑结构、语言规律和跨领域联想，但硬逼它凭空默写冷门 API 的最新参数、或者心算 `423524 × 3124`，就是在逼一个概率预测器干它最不擅长的事。
- **上下文窗口（Context Window）才是零损耗的工作台面**：你通过复制粘贴或文件上传塞进当前对话的 Token 序列（Karpathy 在白板上专门标出了 `tiktokenizer.vercel.app` 用来直观感受文本如何变成 Token 块），相当于直接摊在模型眼皮底下的开卷参考书——只要台面干净、材料精准，推理质量立刻产生质的飞跃。

## 高手日常不堆花哨插件，只死磕这「四大支柱」

看穿了「有损压缩包 + 工作台面」的底层结构后，Karpathy 日常使用 AI 的方法论干净得惊人，全部收敛在四个词里：**Prompts → Context → Tools → Workflows**。

### 1. Prompts（提示指令：把意图、角色与验收格式说透）
好的提示词从来不是去背玄学咒语，而是消除歧义的工程说明书。说清楚「最终要交付什么形态、遵守哪几条硬约束、遇到不确定的地方先反问还是列假设」，不让模型把算力浪费在猜你的心思上。

### 2. Context（上下文装载：给对材料比换更贵的模型还管用）
这是普通用户与重度实践者拉开最大差距的一环。提问前先停三秒钟问自己：**模型要答好这个问题，缺了哪份只有我手头才有的代码文件、报错堆栈或业务背景？** 把最小且充分的一手材料整理成干净纯文本喂进去，同时定期开新窗口清理已经跑偏的历史噪音，不让垃圾上下文污染后续注意力。

### 3. Tools（工具挂载：把确定性的活外包给确定性引擎）
在实录演示中，当面对多位数乘法 `423524 * 3124` 时，Karpathy 展示的正确姿势是让模型直接编写并运行两行 Python 代码拿到精确解 `1,323,120,216`；当面对近几个月的新动态或深度课题时，直接开启联网检索（Web Search）与深度研究（Deep Research）。
**核心分工极其明确：让概率大模型负责理解意图、拆解步骤与编写脚本；让确定性的编译器、计算器与搜索引擎去保证事实与数字 100% 准确。**

### 4. Workflows（高效工作流：选对模型档位，串成顺滑流水线）
高手的关键不在于同时订阅二十个套壳小工具，而在于知道**什么活该派给谁**：
- 日常高频速查、文本格式化、初步头脑风暴 → 派响应飞快的主力多模态快模型；
- 复杂架构规划、棘手 Bug 根因推理、严密数学与代码攻坚 → 派愿意花几分钟深度思考的强化学习推理模型（Reasoning Model），泡杯咖啡等它把逻辑链条推演到底。

## 分水岭：从「人肉陪聊」跨越到「自治系统」的三个核心概念

如果你只想把个人日常提效翻一倍，上面四大支柱已经绰绰有余。但正如 `@Nozelcode` 在帖末重点划出的那句提醒——**如果你想真正跨越分水岭，从「坐在屏幕前一句句跟 AI 聊天」进化到「搭建一套自己运转、替你干活的 AI 系统」，你必须吃透下面这三个核心架构原语：Harness、Loops 与 Graphs。**

:::diagram-pillars-to-system:::

| 系统原语 | 工程本质 | 落到实际项目里长什么样？ |
| :--- | :--- | :--- |
| **Harness**<br>运行底座 / 护栏容器 | 包裹在裸模型外面的整套执行环境、工具接口与安全边界 | 就像赛车的底盘与方向盘：负责自动拼装上下文（如读取 `CLAUDE.md` / `SKILL.md`）、提供沙盒文件读写、记录日志，并拦住越权危险操作 |
| **Loops**<br>反馈自检闭环 | 打破「一锤子买卖」，建立「生成 → 检验 → 纠错」自动循环 | 让模型写完代码自己跑一遍构建与测试；报错信息自动回灌进下一轮输入修正，直到测试全绿或触达最大重试上限才停下交卷 |
| **Graphs**<br>有向状态工作流图 | 把单线程长对话拆解为带条件路由、分支与并发的节点网络 | 复杂任务先由规划节点拆成子任务，分发给几个干净独立上下文的工作节点并行处理，最后汇合到评审节点交叉核验输出 |

可以用一个极形象的公式把整套方法论串起来：

```text
单次高质量回答 = 选对模型 × (清晰 Prompt + 精准 Context + 确定性 Tools)
可信赖自治系统 = 稳固 Harness × (有向编排 Graphs + 自动验证 Loops)
```

## 带回我们自己工作台的三条行动清单

看完这场 70 分钟实操浓缩下来的精华，不需要焦虑去追明天又新出的某个花哨框架，今天就能在自己的工作流里落地三件事：

1. **先把你的高频背景变成随时可投喂的 Context 包**：把常写的项目架构说明、代码审美禁令、个人文风规则存成干净的本地 `.md` 或纯文本端点，告别每次重头口述背景。
2. **凡事多问一句「这步该不该交给代码工具跑」**：凡是涉及统计字数、格式校验、数据计算、链接死活检查，一律让 AI 写小脚本实跑验证，绝不靠肉眼相信它的口头保证。
3. **在重复性工作上先搭最小 Loop**：无论是审代码还是写自媒体脚本，先定一条客观的检查标准（比如语法自检脚本、禁用词扫描器），让 AI 养成「自己先过一遍筛子再端上桌」的习惯。
